## Critical

1. Failed agent runs are reused as if successful (`blueprint_orchestrator.py`). Only completed runs may be reused; retries need distinct attempts/idempotency and the merge barrier must require every required run to be completed.
2. Pause/cancel has a tail race (`blueprint_orchestrator.py`, `blueprint_service.py`). Recheck desired state after every agent, before batch completion, before merge, and before publication; completion must be an atomic conditional transition from running.
3. Candidate acceptance is stale and non-atomic (`blueprint_service.py`). In one `BEGIN IMMEDIATE` transaction require `request expected == candidate.base_version_id == artifact.current_version_id`, conditionally transition `passed -> accepted`, and write the formal version, impacts, and ledger without partial state. Reject/accept races must be safe.
4. The draft firewall only scans keys/provenance (`blueprint_service.py`). Replace free-form copied reference dimension values with a strict abstract mechanism DTO and scan the final actual generation request against reference text/quotes/fingerprints as well as provenance.
5. The candidate flow bypasses structural and rare-phrase gates (`blueprint_service.py`). Load persisted reference ordered beats, style fingerprints, mappings, and rare phrases; feed real inputs into the deterministic assessment and consume a validated typed safety-agent verdict.
6. Agent outputs are not consumed (`blueprint_orchestrator.py`, `blueprint_service.py`). Define/validate per-agent output contracts; consume target-setting, extraction, interpretation/conflict, mapping, and target-blueprint outputs. Persist real hierarchy/edges/interpretations and merge batch -> chapter/volume/work rather than overwriting with the final batch or using fixed prose.

## Important

1. Blueprint publication/editing is not transactional. Artifact version, nodes, evidence, interpretations/conflicts, dependencies, impacts, and ledger must share one transaction; add failure-injection rollback tests.
2. Normal schema-v5 startup does not recover running jobs/batches. Always convert interrupted running work to resumable/paused without automatically invoking a model.
3. Reference submission is not idempotent. Use a stable project/source-hash/rights/prompt key and atomically return the existing source/job on duplicates, including concurrent duplicates.
4. BlueprintRepository write APIs allow cross-project foreign references. Validate every referenced object in the same transaction and reject mismatches as `KeyError`; add database-level protection where practical.
5. Evidence outside the local batch is clamped. Validate `0 <= start < end <= batch_length` before completing the run, record `evidence_invalid`, and block merge.
6. Public job API leaks checkpoint/agent-derived text. Replace subtraction sanitization with an explicit response allowlist containing only identifiers, hashes/counts, state, progress, timestamps, and safe errors.
7. UI lacks author confirmation/editing. Add interpretation/conflict decisions, editable structured target-setting fields with explicit confirmation before migration, and meaningful reference blueprint field editing.
8. Missing-agent automation should return stable `automation_unavailable`, and a no-model manual path must allow creation/versioning of reference and target blueprints/settings.
