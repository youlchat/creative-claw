# Phase 2.5 参考文本逆向与差异化草稿 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户从短文本或整部长篇生成带证据的完整创作机制蓝图，用自然语言新设定迁移为新作品生产蓝图，再按生产单元生成经过上下文隔离和分层相似度门禁的草稿候选。

**Architecture:** 在 schema v5 上新增蓝图任务、批次、代理运行、节点、证据、解释、冲突、映射、候选和相似度记录。`BlueprintOrchestrator` 以确定性 DAG 编排专业代理，`BlueprintService` 负责版本、影响和候选生命周期；浏览器“蓝图实验室”调用同一 API。短文本同步完成，长篇持久化分批并由本地后台执行器运行。

**Tech Stack:** Python 3.11+、Flask 3、SQLite、原生 JavaScript、Python `unittest`、Node 内置测试、Playwright、OpenAI-compatible Chat Completions API。

## Global Constraints

- 多代理是基础架构，但代理只能由确定性 DAG 编排，不能自由推进工序。
- 默认分析所有适用维度；每个维度必须是 `observed`、`not_observed` 或 `uncertain`，不能省略。
- 每个 observed/uncertain 结论必须有合法 reference evidence 范围、置信度和 agent run。
- 20,000 字符以内默认即时任务；更长输入按章或约 12,000 字符分批，重叠不超过 800 字符。
- 草稿代理不得读取参考原文、quote、source locator 文本、稀有短语或抽取代理原始回复。
- 相似度代理可以读取参考内容，但只能返回指标、定位和整改建议。
- 表达复制硬阻止；独特结构一一对应进入 review_required；抽象机制相似允许。
- AI 只产生 candidate/proposal，接受后才创建正式 artifact version；拒绝不修改正式稿。
- 用户必须显式启动抽取、迁移和单元草稿；后台恢复不得自动产生模型费用。
- 自动测试默认不得调用真实模型；真实验证仅在 `CREATIVE_CLAW_REAL_LLM_TEST=1` 时运行。
- API Key 不进入源码、SQLite、浏览器存储、日志或报告。
- 项目不是 Git 仓库；不得自动初始化 Git，每项提交步骤只记录建议提交信息。
