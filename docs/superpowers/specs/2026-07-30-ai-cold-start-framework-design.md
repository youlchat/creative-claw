# AI 冷启动框架搭建设计

**日期：** 2026-07-30  
**状态：** 已确认，待实施计划  
**适用范围：** Creative Claw 右侧 AI 助手

## 目标

让作者在空项目中只输入一句创作意图，例如“帮我写一个类阿凡提的幽默故事”，即可生成一份可审阅的轻量故事骨架。作者确认后，一次性建立项目标题、故事梗概、实体与关系、场景卡和主人公 K 线，不再逐项手工创建。

## 产品边界

- 入口位于右侧 AI 助手现有工作模式下拉框，与“分析”“一致性检查”“续写”“改写”并列，名称为“冷启动框架搭建”。
- 仅空项目可使用。项目已有资料、实体、关系、场景、K 线、生产单元或交付物时，生成与采用都应拒绝，并提示作者新建空项目。
- 项目自身及其 `project.created` 账本事件不影响“空项目”判断。
- 默认生成轻量骨架：3–5 个实体、必要的实体关系、6–8 个场景卡、1 名主人公的一条状态 K 线。
- 冷启动只生成场景卡级摘要，不直接生成完整正文。
- 生成结果必须先预览，作者点击“采用全部”后才写入项目。
- 本功能不追加或覆盖现有正典，也不提供部分采用。

## 交互设计

作者在 AI 助手工作模式中选择“冷启动框架搭建”后：

1. 输入框占位文案变为“例如：帮我写一个类阿凡提的幽默故事”。
2. 主按钮文案变为“生成框架预览”。
3. 页面检查当前项目是否为空。非空时禁用生成按钮，并显示“冷启动仅适用于空项目，请先新建项目”。
4. 作者输入一句话并生成，AI 消息流展示结构化预览卡，而非普通聊天文本。
5. 预览卡依次展示：
   - 故事标题与一句话梗概；
   - 3–5 个实体及类型、定位和必要关系；
   - 主人公、状态维度和 K 线概览；
   - 6–8 个按故事顺序排列的场景卡及每场 OHLC 数值。
6. 预览卡底部提供“重新生成”和“采用全部”。重新生成会丢弃当前预览并依据同一句输入重新请求模型。
7. 点击“采用全部”后按钮进入处理中状态。成功后刷新项目选择器、画布、正文面板、K 线和账本，并在 AI 助手中显示创建数量摘要。

普通“分析”“一致性检查”“续写”“改写”的现有上下文预览和候选审阅流程保持不变。

## 结构化预览契约

模型输出经服务端解析、规范化和校验后形成以下逻辑结构：

```json
{
  "title": "故事标题",
  "premise": "一句话梗概",
  "protagonist_key": "character_1",
  "kline_dimension": "机智主动权",
  "entities": [
    {
      "key": "character_1",
      "name": "原创名称",
      "entity_type": "character",
      "description": "人物或实体定位"
    }
  ],
  "relations": [
    {
      "source_key": "character_1",
      "predicate": "对抗",
      "target_key": "character_2"
    }
  ],
  "scenes": [
    {
      "title": "场景标题",
      "summary": "场景卡级摘要",
      "story_time": "故事内时间",
      "entity_keys": ["character_1"],
      "ohlc": {"open": 35, "high": 58, "low": 28, "close": 52}
    }
  ]
}
```

服务端必须实施以下约束：

- `title`、`premise`、主人公和 K 线维度非空。
- `entities` 为 3–5 项，`key` 在预览内唯一，且 `protagonist_key` 指向 `character` 实体。
- 实体类型限定为 `character`、`location`、`object`、`organization` 或 `canon_fact`。
- 每条关系的两端必须引用预览中存在的实体。
- `scenes` 为 6–8 项；标题与摘要非空；引用的实体必须存在。
- 每个场景恰好有一根主人公 K 线。数值在 0–100 内，并满足 `low <= min(open, close)` 与 `high >= max(open, close)`。
- 为形成连续曲线，服务端先把 OHLC 四值四舍五入到一位小数，再把第二个及以后场景的 `open` 设置为前一场景规范化后的 `close`，随后仅在必要时把 `high` 扩展为 `max(high, open, close)`、把 `low` 扩展为 `min(low, open, close)`。缺少任一 OHLC 字段时不得猜测，必须判定结构无效。
- 模型输出若包裹在 Markdown JSON 代码块中可正常解析；结构不合法时允许一次自动格式修复请求，仍不合法则返回可理解的错误，不产生项目写入。

## 原创性约束

当输入包含“类某作品、人物或传统故事”等参照时，生成提示只允许使用高层机制，例如机智反转、民间幽默、讽刺权威、寓言式因果。不得复刻参考对象的专有角色名、完整情节、标志性台词或连续表达。预览仍可显示作者的原始输入，但生成的实体、场景和正文摘要必须是原创内容。

## 组件与职责

### 浏览器端

`creative_claw/web/index.html` 增加冷启动模式选项和可复用的预览卡容器。`creative_claw/web/app.js` 负责模式切换、空项目状态提示、请求预览、渲染结构化结果、重新生成、采用全部和成功后的画布刷新。`creative_claw/web/app.css` 提供预览卡、实体标签、场景列表、K 线数值和操作区样式。

浏览器保存当前预览对象用于展示，但服务端在采用时会重新执行完整校验；浏览器状态不能绕过空项目检查或数据约束。

### 冷启动领域服务

新增聚焦的冷启动模块，负责：

- 判断项目是否为空；
- 构造结构化生成提示；
- 调用现有 OpenAI-compatible 模型连接；
- 解析和校验预览契约；
- 在一个数据库事务中应用整份预览；
- 返回创建数量和最新画布快照。

普通 RAG 聊天继续使用现有 `/chat` 路径。冷启动不检索项目证据，因为它只允许空项目使用，也不把结构化生成混入普通回答协议。

### HTTP API

增加两个专用端点：

- `POST /v1/projects/<project_id>/cold-start/preview`
  - 输入：`{"prompt": "一句创作意图"}`
  - 行为：检查空项目，调用模型，返回 `{"preview": {...}, "generation": {"prompt": "...", "model": "..."}}`；不写项目数据。
- `POST /v1/projects/<project_id>/cold-start/apply`
  - 输入：`{"preview": {...}, "generation": {"prompt": "...", "model": "..."}}`，内容原样来自上一步预览响应。
  - 行为：再次检查空项目和完整契约，在单一事务中写入全部数据并返回最新画布快照。

## 采用时的数据映射

- 预览 `title` 更新当前项目名称；`premise` 写入冷启动账本事件载荷，并作为各场景的共同框架摘要保留在首场景属性中。
- 每个实体写入 `entities`；描述放入 `attrs.description`，预览键只用于本次事务内解析关系，不写成长期业务标识。
- 每条关系写入 `relations`，分支固定为当前 `main`。
- 每个场景按顺序写入 `timeline_events`：`episode=1`，`scene=1..N`，`label=title`，`description=summary`，并在属性中标记 `status=outline`、`format=scene_card` 和参与实体 ID。
- 每个场景的 OHLC 写入 `ohlc_points`，人物名称取主人公实体名，维度取 `kline_dimension`，周期为 `scene`，周期标识为 `E1-S01..E1-S0N`，并通过 `timeline_event_id` 关联对应场景。
- 整包采用只写入一条 `cold_start.applied` 账本事件，载荷包含原始创作意图、标题、创建对象 ID、数量和模型信息。该事件与所有实体、关系、场景和 K 线写入使用同一数据库连接和事务。

## 事务与并发

采用请求在事务开始后重新统计项目内容。若项目在预览后被其他操作写入，返回 HTTP 409，保留预览供作者查看，但不写入任何对象。所有实体、关系、场景、K 线、项目标题和账本事件共同提交；任一校验或数据库写入失败时共同回滚。

## 错误处理

- 模型未配置：沿用现有模型配置入口，提示“请先连接模型”。
- 输入为空：阻止请求，并把焦点留在输入框。
- 项目非空：返回 409 和“冷启动仅适用于空项目，请先新建项目”。
- 模型网络错误：保留作者输入，恢复生成按钮并显示可重试提示。
- 模型输出无法解析或校验失败：自动进行一次格式修复；仍失败则显示“框架格式不完整，请重新生成”，不暴露原始推理文本。
- 采用事务失败：返回错误并保持预览卡可见，数据库不保留半成品。
- 重复点击：生成和采用期间禁用对应按钮，服务端仍以空项目检查保证幂等安全。

## 测试策略

### 单元测试

- 合法结构可被规范化并通过校验。
- 少于 3 或多于 5 个实体被拒绝。
- 少于 6 或多于 8 个场景被拒绝。
- 未知实体引用、非人物主人公和非法 OHLC 被拒绝。
- 小数 OHLC 被四舍五入到一位；连续场景的 `open/close` 断裂按既定规则修正，并相应扩展 `high/low` 包络。
- 只有项目记录和 `project.created` 账本事件时判定为空；任一资料、实体、关系、场景、K 线、生产单元或交付物存在时判定非空。
- Markdown 代码块 JSON 能被解析；第一次无效响应触发一次修复，第二次无效则失败。

### API 与事务测试

- 预览成功后项目快照没有变化。
- 非空项目的预览和采用均返回 409。
- 采用成功后项目标题、3–5 个实体、关系、6–8 个场景、等量关联 K 线和一条 `cold_start.applied` 账本事件全部存在。
- 注入中途数据库错误后，标题与所有新对象均回滚，账本仍通过哈希连续性校验。
- 预览后出现并发写入时，采用返回 409 且不追加冷启动数据。

### 浏览器测试

- AI 助手下拉框出现“冷启动框架搭建”。
- 选择该模式后占位文案和主按钮正确变化。
- 非空项目显示阻止提示。
- 空项目可生成包含梗概、实体、K 线与场景的预览卡。
- “重新生成”替换当前预览；“采用全部”成功后画布、正文选择器、K 线板和账本同步刷新。
- 切回普通模式后原有上下文预览、聊天、续写与一致性检查行为不变。

### 回归验证

运行完整 Python 单元测试、Node 测试、JavaScript 语法检查和现有浏览器 E2E；真实付费模型测试继续默认跳过，除非显式设置已有的真实模型测试开关。

## 完成标准

作者能在一个空项目中选择“冷启动框架搭建”，输入一句创作意图，看到符合数量和 K 线约束的原创轻量骨架，点击一次“采用全部”后在中央画布看到完整实体、关系、6–8 个场景卡和关联 K 线。整个流程无需手工新增实体、场景或 K 线，且不会污染非空项目或留下部分写入。
